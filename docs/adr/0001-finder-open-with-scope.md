# Finder 临时打开覆盖未知文件类型，内容支持仍限定为文本

Textlet 的 Finder 临时打开能力覆盖纯文本文件的任意扩展名及无扩展名情形，接受更宽的系统类型声明可能使 Textlet 出现在非文本文件候选中的取舍；打开时拒绝可识别的二进制内容，普通文本不能无损解码时提示编码问题。临时打开不主动修改默认打开应用，应用内文件关联设置保留现有固定列表，避免将宽泛的打开能力转化为宽泛的默认应用设置。

Finder 与应用内打开共用内容检查，并沿用现有大小规则：不超过 8MiB 的文本可编辑，超过 8MiB 自动进入只读日志模式，保留该模式现有的编码支持范围。普通编辑由用户主动保存写回来源文件；重复打开复用已有标签并保留未保存内容，多文件打开中的单个失败不阻断其余文件。

Textlet 的低内存、低 CPU 定位优先于完整的文件格式检测：仅检查文件开头至多 16KiB，优先复用已有读取缓冲，不为检测增加全文扫描或常驻后台任务，在启动日志行号索引之前拒绝可识别的二进制内容。先识别 UTF-16/32 BOM，避免将编码中的零字节误判为二进制；接受只有文件后部出现二进制内容等特殊情况可能无法提前识别的限制，普通编辑仍执行原有完整解码检查。

完整需求与验收场景见 [GitHub Issue #1](https://github.com/trrywui/textlet/issues/1)。

实现采用独立的 `Editor` / `Alternate` 文档声明，覆盖 `public.text` 与 `public.data`，不导出自有未知类型，也不改变固定文件关联设置。macOS 14 实测中，未知动态类型可通过“其它…”选择，但一级候选菜单不保证列出 Textlet；这一入口满足临时打开的需求。普通文本复用既有缓冲与解码器确认无 BOM 的宽字符编码，保存时保留原字节序和 BOM 状态。只读日志的前检文件描述符交给现有查看器复用，避免再次读取探测窗口。

实施验证、资源测量与系统界面验收边界见 [2026-10-10 验证报告](../Finder临时打开验证-2026-10-10.md)。
