# Sublime Text 正常模式对照（2026-09-28）

这次用本机的 Sublime Text 做成熟编辑器参照，重点看大窗口下连续编辑、滚动、空闲 CPU 和内存。

## 结论

测试前用户已经备份文本并完全退出 Sublime。测试程序直接启动普通模式，使用正常的用户配置、插件宿主和恢复的会话，没有使用 `--safe-mode`。Build 4215 的窗口实际保持在 1680×968，前台状态和大窗口检查全程通过。

临时文件从 36,611 个 UTF-16 字符变为 36,771 个，说明编辑确实写入并保存成功；160 次滚动操作也全部执行。

Sublime 正常模式主进程的内存明显高于本次 Textlet 测试：输入阶段最高约 806.5 MiB，停止输入后约 500.4 MiB；进程族（主进程加 `plugin_host`）输入峰值约 829.5 MiB，输入后约 523.5 MiB。它会回落，但仍然保留在几百 MiB，而不是几十 MiB。

在本轮命令驱动路径下，Sublime 的编辑器进程 CPU 低于 Textlet 两个实现，停止操作后也回到接近空闲。不过 CPU 只能作为同条件下的量级参考，不能据此断言真实键盘输入和中文输入法路径也完全相同。

## CPU 对照

百分比是占一个 CPU 核心的比例；100% 约等于占满一个核心。

| 阶段 | Textlet 原版平均 / P95 | Textlet 实验版平均 / P95 | Sublime 正常模式平均 / P95 |
| --- | ---: | ---: | ---: |
| 连续输入 | 31.3% / 50.5% | 91.9% / 100.5% | 5.9% / 6.5% |
| 输入后空闲 | 1.62% / 17.3% | 0.19% / 0.23% | 0.29% / 1.34% |
| 连续滚动 | 18.9% / 42.1% | 31.8% / 73.2% | 4.2% / 6.1% |
| 滚动后空闲 | 2.17% / 17.1% | 0.16% / 0.23% | 0.12% / 0.03% |

Sublime 的输入阶段测得约 1.13 CPU 秒，滚动阶段约 0.82 CPU 秒；输入后空闲约 0.022 CPU 秒，滚动后空闲约 0.010 CPU 秒。

## 内存对照

下表使用主进程当前 `phys_footprint` 的阶段最高值和结束值。Sublime 的 `plugin_host` 还额外占用约 23 MiB。

| 阶段 | Textlet 原版最高 / 结束 | Textlet 实验版最高 / 结束 | Sublime 正常模式主进程最高 / 结束 |
| --- | ---: | ---: | ---: |
| 连续输入 | 176.2 / 131.6 MiB | 81.6 / 77.3 MiB | 806.5 / 500.4 MiB |
| 输入后空闲 | 131.8 / 131.8 MiB | 77.3 / 77.3 MiB | 500.5 / 500.4 MiB |
| 连续滚动 | 135.8 / 135.7 MiB | 82.7 / 81.5 MiB | 617.3 / 555.6 MiB |
| 滚动后空闲 | 135.7 / 135.7 MiB | 81.5 / 81.4 MiB | 555.6 / 494.4 MiB |

本次 Sublime 在进入输入阶段前的正常会话基线约为 752 MiB，输入峰值约 807 MiB，停止后回落到约 500 MiB。这个数包含正常会话里已经恢复的标签页、插件状态和缓存，不能单独归因于编辑器绘制；它代表的是“你平时启动正常 Sublime 后”的实际基线。

## 测试方式和限制

测试先放入 240 行中英文、中文和 emoji 混合的密集文字，然后执行 160 次输入、等待约 8 秒、执行 160 次滚动、再等待约 8 秒。窗口目标为 1680×940，实际窗口高度因系统边框为 968，Retina 倍率为 2。

macOS 辅助功能权限没有授予测试程序，模拟的全局键盘事件不会可靠进入 Sublime 的编辑区。因此正常模式使用 Sublime 自己的 `subl --command` 接口逐字执行 `insert_snippet`，再执行 `save`；滚动使用 `scroll_lines`。这测到的是 Sublime 编辑器命令和绘制路径，包含正常模式插件和会话的主进程开销，但不包含真实中文输入法候选窗，也不等同于物理键盘事件分发。

CPU 汇总包括 Sublime 主进程及其发现的 `plugin_host` 子进程；调用命令的短生命周期 `subl` 辅助进程没有计入。这个区别会让 Sublime 的 CPU 数字偏向“编辑器内部处理成本”，所以它适合回答“正常编辑器自身是否持续高负载”，不适合作为完整输入链路的严格竞赛成绩。
