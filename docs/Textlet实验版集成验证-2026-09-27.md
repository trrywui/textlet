# Textlet 实验版集成验证 · 2026-09-27

## 交付

可运行应用：`build/Textlet Rows.app`，显示名称“Textlet 实验版”。构建命令：`bash scripts/build-experimental.sh`。

这是带完整应用功能的独立实验版本。默认草稿目录为 `~/Library/Application Support/Textlet-Rows-Experiment/`，应用标识为 `local.textlet.rows-experiment`。它不会自动导入正式版草稿，也没有覆盖已有的 `build/Textlet.app`。

保留 NSTextView / TextKit 的输入、排版、撤销、系统查找替换以及现有标签、高亮、行号、JSON 格式化、大日志查看和会话保存。正文绘制使用可见行图片，纯色背景和选区使用图层。与此前最小原型不同，没有原型的 128Ki UTF-16 正文限制，也不在每次按键后重新排版整个文档。仍受 TextKit 自身排版和应用现有大文件策略约束。

## 实现与排查

- `ROW_RENDERER` 编译条件启用 `RowRenderingTextView`；普通构建继续使用原绘制路径。
- 行缓存比较文字、属性、绘制范围与像素倍率，只重画有变化的行；滚出视口的行图片会移除。
- 换行控制字符不计入墨迹边界，避免短行也分配整个窗口宽度的图片。
- 临时高亮属性参与图片缓存比较；允许 TextKit 把临时属性应用到用于屏幕显示的行图片。
- 最初的像素检查使用 `Data` 的哈希值，不同图片发生相同哈希，导致纯文本切换误报失败。最终改为复制并逐字节比较全部像素；高亮→纯文本→高亮的往返检查通过。旧的失败记录保留，不能把哈希误报解释成仍存在的颜色故障。

## 最终完整实验版的内存

来源：`final-rows.json`。小窗口860×590、大窗口1680×940 points，Retina 2×。180个逻辑行的中文、英文、emoji密集文本；每150ms替换首字符，每100ms采样。全部阶段采样均在前台，画面检查与截图在停止内存采样之后进行。

**本轮为 AMD 独显条件 `GFX0`，运行前后 `SwitchCount` 均为2。不能和此前 Intel 集显下原版约170MiB直接比较，也不能据此声称系统总内存降低相同比例。** 此前最小原型的集显对照仍见《逐行绘制实验》，不能把原型成绩当作完整实验版成绩。

| 场景 | 阶段采样最高 | 阶段末尾 |
| --- | ---: | ---: |
| 小窗口短文本编辑 | 16.82 MiB | 15.71 MiB |
| 大窗口短文本编辑 | 16.61 MiB | 16.58 MiB |
| 大窗口短文本停止编辑 | 16.63 MiB | 16.63 MiB |
| 大窗口密集文本编辑 | 62.89 MiB | 62.87 MiB |
| 大窗口密集文本滚动 | 67.09 MiB | 66.04 MiB |

整轮系统记录的物理占用峰值 **119.93 MiB**；不能只报采样最高约67MiB。峰值出现在密集文本滚动阶段，说明改变绘制方式之后仍会产生瞬时资源开销。

所有编辑阶段合并的主线程操作 P95 为 **11.56ms**，包含修改、请求可见布局、行绘制和 `displayIfNeeded` 返回，不包含GPU完成和真实按键到屏幕的总延迟。不能把它当作单独密集文本阶段的P95。

`vmmap` 显示密集文本下仍有行位图及 CoreAnimation 缓存；满屏文字、可见行数量、2×像素倍率，以及新旧画面交接都会增加资源开销。保留原生排版也保留了相应的文本、字体和撤销开销。因此本版不能保证所有场景低于30MB或50MB，仍属于可试用的实验方案。

本轮只统计应用的 `TASK_VM_INFO.phys_footprint`，不包含 WindowServer、输入法进程或独显显存；只测一台机器的一轮有效完整流程，没有长时间常驻、多屏和跨系统版本验证。此报告记录的是此前独显验收；随后已补充[完整应用的集显同条件对照](完整应用同条件绘制对照-2026-09-27.md)，请单独阅读，勿混合两轮数据。
