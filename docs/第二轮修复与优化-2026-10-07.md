# Textlet 第二轮修复与优化（2026-10-07）

2026-10-08：本轮修复与 CPU 优化纳入 Textlet 0.5.1（build 8）。下文保留 2026-10-07 的实验记录。

本轮落实第一轮体检的两个已确认问题，并对摘要、行号和内存分配做对照实验。实验均使用隔离会话和合成文件。实验结束时，修改保留在工作区，未提交 Git，也未安装或替换日常使用的应用。

## 功能修复

### 恢复时保留可救回的草稿

当前清单损坏或缺失、需要回退到上一代快照时，先在会话目录创建 `recovery-UUID/`，复制现存两代清单以及 `drafts/` 中的所有 `.txt` 正文。成功归档后才接受回退并覆盖损坏清单。启动后的保存与两代清理不会进入归档目录。

归档失败会中止恢复，保留原清单和正文。恢复提示包含归档的完整路径。归档不会自动删除，方便手动找回较新正文；实际发生恢复时会额外占用磁盘空间。

回归覆盖损坏清单、缺失清单、中断保存留下的孤立正文、连续三次保存后重启，以及归档写入失败。

### 同大小、同修改时间的外部变化

保存文件关联时记录设备、inode、大小、纳秒精度 mtime 和 ctime。状态检查和文件监视使用同一份签名，能识别原 inode 改写以及原子替换，即使修改时间被完整还原。

旧会话没有签名时，按磁盘内容摘要校验，再采用签名。旧会话中的已变化版本按签名缓存校验结果，避免反复读取同一版本。显式保存会更新签名；原有保存冲突的内容摘要校验继续保留。签名变化会保守地提示外部变化，保存时仍以内容摘要判断实际冲突。

回归同时检查真正的文件通知、取消冲突保留双方内容、覆盖后清除状态，以及旧 JSON 和重启后的状态。

## 保留的 CPU 优化

行号缓存最多 128 个标签的尺寸及固定字体属性，继续使用原生 NSString 绘制。不会缓存整份文档的行号图像。延迟布局稳定后，60 组字体、滚动、换行、大行号和续行箭头的像素对比一致。

文本摘要按 32,768 个 UTF-16 单元转换为 UTF-8，再计算相同的 SHA-256。总转换缓冲固定为 160 KiB，不复制整份编辑缓冲；代理对跨块边界和不成对代理单元的替换行为均与原有 UTF-8 摘要一致。编辑、撤销和重做后的保存状态仍立即更新。

## 测量结果

下面的应用指标取本轮两次原始基线与两次最终构建的平均值；缓存均为 32 MiB，各次检查通过，GPU 与前台条件稳定。

| 指标 | 原始基线 | 最终构建 | 变化 |
| --- | ---: | ---: | --- |
| 连续输入 CPU（单核） | 23.43% | 20.77% | 降低 11.4% |
| 连续滚动 CPU（单核） | 26.18% | 23.66% | 降低 9.6% |
| 完整生命周期内存峰值 | 124.80 MiB | 124.89 MiB | 无明显变化 |

空闲阶段仍低于单核 0.3%。中间版本另行关闭行号尺寸缓存，输入/滚动 CPU 为 22.47% / 25.56%，启用时为 20.83% / 23.52%，支持尺寸缓存确有收益。

摘要单独测量每个大小的 40 次等长替换。以下为第一轮原始基线与本轮无其他测试并行的复测，单位 ms；内容状态仍在每次编辑后立即校验。

| UTF-16 长度（ASCII） | 原始 p50 / p95 | 优化后 p50 / p95 |
| --- | ---: | ---: |
| 64 KiB | 0.322 / 0.347 | 0.224 / 0.232 |
| 1 MiB | 5.085 / 5.221 | 3.498 / 3.879 |
| 4 MiB | 20.386 / 20.831 | 14.544 / 18.352 |
| 8 MiB − 1 | 40.648 / 42.069 | 28.778 / 31.753 |

8 MiB 中位耗时降低约 29%，但仍有约 29 ms 的同步开销，并随文本长度增长。进一步降低大文本输入停顿，需要设计能正确处理撤销和恢复的增量内容判定。

## 内存实验的结论

Instruments Allocations 已采集并导出统计及调用位置。轨迹终点仍保留约 31.7 MiB 的 CG raster data 和 31.7 MiB 的 CoreAnimation 分配，图像流转有较多累计临时分配。这些累计分配不能当作瞬时内存峰值。

先验证生成新视口前提前清理旧图像，再验证逐行 autoreleasepool。两种方案的完整生命周期峰值仍在约 124–125 MiB，没有稳定收益，均已撤回。最终没有改动行图像生成和默认 32 MiB 缓存。本轮证实的是 CPU 改善，不能声称常用场景的内存占用已降低。

## 验证结果

最终构建的常规检查共 452 项通过：持久化/文件/功能自测 268 项、语法 7 项、生命周期 101 项、行图像 52 项、完整交互 24 项。

- 行号原生/缓存/重复绘制：60 组像素对比一致；先稳定 TextKit 的延迟布局，避免把第一次绘制缺少尚未布局的行误判为缓存错误。
- 固定种子随机差分：600 次修改、2,400 次行号比较，480 次流式搜索比较，72 个 UTF-8 分页检查，均通过。
- UI 随机探针：360 次切换/编辑及穿插撤销、重做，30 次缓存与重新生成的行图像对比，10 项检查通过。
- 独立会话打开/关闭 240 个临时标签：Note、NSTextStorage 和标签视图的弱引用均释放；末两批当前内存约 84.40 / 84.46 MiB，没有发现该路径持续积累对象。
- 完整交互完成 463 次循环；三标签热退出后的正文、选择和滚动恢复通过。
- 五个文件/草稿场景的热退出恢复通过，文件路径及未保存/缺失状态正确，退出备份没有写入关联源文件。
- 最终 AddressSanitizer 自测 268 项通过，无内存访问错误；额外 UI 探针注入 Main Thread Checker，未报告 UI 线程违规。

Sanitizer 和 Instruments 运行属于诊断，不参与 CPU 收益计算。测试使用程序化输入和合成数据，不能替代日常文件及真实输入法的长时间验证。

## 证据与复现

第一轮原始基线：`test-output/audit-2026-10-07/`。本轮产物：`test-output/followup-2026-10-07/`，包括隔离构建、日志、随机测试、性能 JSON、Instruments 轨迹和构建状态。这些目录均为 Git 忽略的测试输出。

性能驱动为 `Experiments/TextletRows/balance.py`，固定窗口 1680×940、2×、初始 36,611 个 UTF-16 单元、每秒 20 次事件、160 次输入和 160 次实际移动的滚动。单次约 37 秒；各条件顺序执行，编译和其他 GUI 测试不与正式性能测量并行。GPU、前台窗口、实际事件及内容检查必须通过。

CPU 数字按一个逻辑核计，内存使用进程 `phys_footprint`。完整生命周期峰值来自 `peakFootprintMiB`，不能用每 100 ms 的当前内存采样最大值代替。结论限于本机及这些工作负载。

常规复现：

```sh
bash scripts/build.sh test-output/followup-2026-10-07/Textlet.app
test-output/followup-2026-10-07/Textlet.app/Contents/MacOS/textlet --self-test
python3 Experiments/TextletRows/balance.py \
  --app test-output/followup-2026-10-07/Textlet.app \
  --output test-output/new-comparison --name current --budget 32 --scroll-span 20
```

本机 AppKit 初始化需要系统应用服务访问权限。上述测试必须使用独立会话，不能指向日常草稿目录。
