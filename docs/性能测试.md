# Textlet 0.2 · 本机性能与功能验证

测试日期：2026-09-25。macOS 14.8.9（23J631），Intel x86_64，Swift 优化编译。测试使用独立草稿目录和合成文件，没有读取或替换用户笔记。

## 最终版内存

单位统一为十进制 MB；50MB 约等于 47.68MiB。表中均为实际采样值。

| 场景 | 全程采样最高值 | 前台采样最高值 | 后台阶段采样范围 |
| --- | --- | --- | --- |
| 三标签 · 3/30/100 行 | 32.03 MB | 32.03 MB | 28.62–30.89 MB |
| 十标签 · 每个 1200 行 | 39.44 MB | 39.31 MB | 38.21–39.44 MB |
| 三笔记 + 100MB 日志 | 48.59 MB | 48.59 MB | 34.34–47.98 MB |
| 三笔记 + 500MB 日志 | 44.78 MB | 44.78 MB | 33.86–34.03 MB |

这四轮最终版测试的采样最高值均低于 50MB。**这不是任何场景都低于 50MB 的保证**：采样会遗漏瞬时分配；大量笔记、撤销记录、较大 JSON 格式化、窗口尺寸、输入法和长期使用仍会影响结果。

口径：Textlet 自身 `TASK_VM_INFO.phys_footprint`。日志功能测试每 100ms 采样，普通编辑测试每 250ms 采样；同时记录 `NSApp.isActive` 和 RSS。单轮约 13–30 秒，准确时间与采样数见原始 JSON。没有后台样本时明确标注，不用其他轮次补值。窗口截图在采样结束后生成，不计入运行内存结果；普通启动不采样也不截图。

该口径不包含 WindowServer、输入法等独立进程；不能当作整机新增内存，也不能把 RSS、安装包大小和 footprint 混用。测试用程序调用编辑接口并发出菜单快捷键，包含中文和 emoji，但没有模拟真实中文输入法，也不是长时间常驻测试。

## 速度

| 日志文件 | 建立行号索引 | 完整搜索一次（无匹配） | 中间/下一段/末尾跳转中最慢一次 |
| --- | --- | --- | --- |
| 100MB | 0.32 s | 0.50 s | 29.19 ms |
| 500MB | 1.35 s | 2.22 s | 29.71 ms |

索引和搜索在后台执行；跳转时间包含读取分段与可见区绘制。100MB 文件实际为 100,000,032 字节，500MB 文件为 499,999,948 字节。日志每段最多约 48KiB，索引每 256KiB 保存一个检查点。

| 编辑场景 | 插入文字及绘制 P95 | 最慢一次 | 标签切换最慢一次 |
| --- | --- | --- | --- |
| 三标签 | 4.90 ms | 6.20 ms | 41.51 ms |
| 十标签 | 5.02 ms | 5.56 ms | 47.73 ms |

这些是同步调用耗时，不是端到端键盘响应时间。标签切换包括保存草稿。

## 功能检查

最终版所有自动检查通过：

- `⌘⇧J` 实际菜单快捷键触发；只格式化所选 JSON；周围文字不变；一次撤销和重做；非法 JSON 保持原文。
- JSON 大整数、小数/指数表示、键顺序、重复键、中文和字符串转义保留；拒绝语法错误、过深嵌套和超限输入。
- 普通笔记行号、CR/LF/CRLF、空文档、尾随换行、修改后的行号缓存；软换行显示效果通过窗口截图检查。
- 日志分段连续无缺漏、长单行有界、中文/emoji 边界完整、跨读取缓冲边界搜索、全文件无匹配搜索、末尾定位和选中匹配文字。
- 大日志自动只读、编辑笔记与日志来回切换、日志不进入草稿正文和撤销记录、源文件变化时要求重新载入。
- 三/十标签编辑的纯文本粘贴、独立撤销和重做、滚动位置，以及退出后正文/标题/光标/视口恢复。
- 100MB/500MB 日志真正退出并重新启动，恢复当前标签、字节位置、行号、段内视口，同时验证其他三条笔记正文；另用中间字节位置和 1000px 段内滚动位置，连续退出、重启两次验证非零视口恢复。
- 旧版 v1 会话兼容、外部日志缺失不影响其他草稿、损坏快照回退和同目录单写入锁。

## 优化过程与保留结果

早期使用系统标尺并且未限制行号绘制范围的试验，100MB 测试曾达到 197.84MB / 203.38MB。换成轻量行号栏后降到约 60MB；随后修复 macOS 14 下 dirtyRect 超出视图边界导致的大面积越界绘制，正文显示与内存进一步改善。最终仅绘制可见行号，并采用稀疏检查点、批量字符读取和增量缓存，避免逐行重复扫描；改为直接读取可见区已排版的行片段，使用 withoutAdditionalLayout 接口，避免行号绘制间接要求全文排版；直接使用原生 UTF-16 文本缓冲，减少 Swift String 桥接后的随机字符读取开销。

中途一次重启检查的“预期正文”错误地取用了已释放的内存缓冲，导致两项比较失败；磁盘草稿仍在。测试改为从已保存草稿读取预期值后，在最终版本重新运行并全部通过。未把这些中间轮次作为交付结果。

十标签编辑中，原生文本缓冲读取调整前的输入 P95 约 60ms，最终版为约 5ms；完整测量见各轮原始数据。

原始中间轮次和最终轮次均保存在 [Benchmarks/v0.2](../Benchmarks/v0.2/)，分别用 `100-a`、`100-b`、`100-c`、`500-d`、`release-*`、`delivery-*` 等名称区分。最终验收使用 `delivery-*`；不会用低峰值轮次替换同一版本的较高结果。0.1 报告另存于 [性能测试-0.1.md](性能测试-0.1.md)。

## 使用范围

支持 JSON 格式化、行号及大日志只读分段查看。大日志支持 UTF-8/ASCII 字面搜索，区分大小写，无正则、无自动追踪追加、无全文件连续编辑；全选/复制仅作用于当前段。JSON 单次输入限 2MiB、输出限 8MiB、嵌套限 128 层。语法高亮仍未实现。
